FLAGSHIP PROJECT Security Tooling Offensive + Defensive

MshindiSecure

A dual-purpose cybersecurity platform combining offensive penetration testing utilities with a production-ready defensive monitoring system. Designed for organizations that need to both audit their own infrastructure and actively protect live login systems against injection attacks, credential stuffing, and brute-force campaigns — in real time.

FOUNDER Ephy Mshindi

Key Features

Real-Time Login Monitoring
Continuous surveillance of login events across monitored endpoints, flagging anomalous patterns within milliseconds of detection.
SQLi Pattern Engine
Multi-layer SQL injection detection using signature matching, heuristic analysis, and parameterized query enforcement.
Brute Force Throttling
Adaptive rate-limiting with progressive lockout, CAPTCHA escalation, and automatic IP blocking on threshold breach.
Incident Dashboard
Operator-facing panel displaying live threat feed, blocked IPs, attack vectors, and session anomaly classifications.
Pentesting Utilities
Offensive tools for authorized testing: form fuzzing, header injection probes, session token analysis, and directory enumeration.
Alert & Audit Logging
Structured log output compatible with SIEM ingestion. Every threat event is timestamped, classified, and persisted for forensic review.

The platform operates as a middleware layer, intercepting authentication requests before they reach the application database. The Python detection engine applies rule-based and heuristic analysis to each request payload, with sub-millisecond evaluation time. Flagged requests trigger a three-tier response: log → alert → block, allowing operators to configure aggression thresholds based on environment risk profile.

Security Implementation

SQL Injection Prevention
Dual-layer defense: input sanitization at the request boundary + parameterized queries enforced at the data layer. Pattern library covers UNION-based, blind, time-based, and error-based SQLi variants.
Brute Force Defense
Rate limiting per IP and per user account. Exponential backoff on repeated failures. Automatic lockout with configurable thresholds. IP reputation cross-reference for known bad actors.
Session Anomaly Detection
Flags credential stuffing via impossible travel detection, user-agent drift, and session token reuse patterns. Suspicious sessions are quarantined and queued for operator review.
Threat Classification
Every incident is tagged by attack type, severity level, and confidence score. Classification informs automated response and provides structured data for downstream SIEM or SOC tooling.

Challenges & Solutions

Problem
Distinguishing legitimate high-frequency login attempts (API clients, mobile apps) from credential stuffing attacks without triggering false positives on valid users.
Solution
Built a behavioral profiling layer that establishes per-client request baselines. Alerts only fire when deviation from baseline exceeds configurable statistical thresholds — not on raw volume alone.
Problem
Attackers rotate IP addresses to bypass simple IP-based rate limiting, making per-IP blocks insufficient as a primary defense.
Solution
Shifted rate limiting to the account layer rather than solely IP-layer. Combined with fingerprinting via User-Agent, device signals, and timing patterns to detect distributed attacks from rotating IPs.
Problem
Obfuscated SQL injection attempts (URL-encoding, comment injection, case variation) bypassing basic regex-based filters.
Solution
Implemented input normalization before pattern matching — decoding all common obfuscation layers before analysis. The detection engine evaluates the decoded payload, not the raw string.

LIVE · 80+ USERS Full Stack Real-Time Platform

SPACE-Y

A full-featured social discovery platform built for real-time human connection — combining live chat, peer-to-peer voice and video calls, a swipe-based user discovery engine, and an administrative control panel. Currently serving an active user base of 80+ with zero downtime since launch, built entirely on a security-conscious architecture.

SPACE-Y is built on a single-origin API design — all client state is validated server-side before persistence. The React frontend communicates with the Node.js API layer for business logic, while Supabase Realtime subscriptions push live events (messages, matches, call invitations) directly to connected clients. WebRTC signaling is brokered through Supabase, keeping media traffic peer-to-peer and off the application server.

Security Implementation

Auth & Session Security
JWT-based authentication with Supabase Auth. Tokens are short-lived with refresh rotation. All sessions are server-validated — client-side auth state is treated as untrusted.
Row-Level Security
Supabase RLS policies enforced at the database layer. Users can only access their own records and explicitly granted shared data — even if the API layer is bypassed.
Input Validation
All user input sanitized at the API boundary. Message content, profile fields, and media uploads are validated against schema and stripped of executable payloads.
Rate Limiting & Abuse Controls
API routes rate-limited per authenticated user. Swipe and message endpoints have additional throttling to prevent spam patterns. Repeated violations trigger temporary suspension flagged for admin review.

Challenges & Solutions

Problem
WebRTC call setup failing for users behind restrictive NAT or corporate firewalls, causing connection drop rates that made the calling feature unreliable.
Solution
Implemented STUN/TURN server configuration in the WebRTC offer/answer flow. TURN relay is used as a fallback, ensuring near-universal connectivity at the cost of media routing through the relay server.
Problem
Real-time message subscriptions creating n² Supabase channel connections as user count grew — leading to performance degradation and connection limit pressure.
Solution
Refactored to a single multiplexed channel per user with server-side filtering. Reduced active connections by ~80% while maintaining sub-100ms delivery latency across all active conversations.
Problem
Admin panel exposing sensitive user data to any authenticated user who discovered the admin routes — IDOR vulnerability in early implementation.
Solution
Implemented role-based access control at both the API middleware layer and the Supabase RLS layer. Admin routes require a verified admin role on the JWT — authorization is validated server-side on every request.

The most valuable decision in SPACE-Y's architecture was enforcing authorization at the database layer via Supabase RLS, not just the API layer. It meant that even if an attacker bypassed the Node.js middleware entirely — via a misconfigured route, a logic bug, or direct SDK access — they would still hit a wall at the data layer. Defense in depth isn't a checkbox; it's a structural commitment.

LIVE · E-COMMERCE Full Stack Artisan Marketplace

CraftyHands

A production e-commerce platform purpose-built for artisan sellers of handmade and hand-crafted clothing. CraftyHands handles the full commercial lifecycle — product discovery, filtering, cart management, checkout, and a seller dashboard — on a secure, real-time backend. Built to prove that indie crafters deserve the same quality of digital storefront as large retail brands.

Cart & Checkout Flow
Persistent cart state with quantity management, item removal, and a multi-step checkout experience designed for low drop-off rates.
Seller / Admin Dashboard
Sellers manage inventory, upload product images, set pricing, and track orders — all from a protected dashboard with role-based access.
Product Image Uploads
Secure file uploads to Supabase Storage with CDN delivery — optimized for fast load times even on slower mobile connections.

CraftyHands follows a clean separation between UI and data layers. React handles all client-side rendering and state — cart, filters, and session — while the Node.js API processes business logic like order creation and role verification before touching the database. Supabase Row-Level Security ensures that even a direct SDK call from a rogue client cannot access another user's orders or seller inventory.

Security Implementation

Role-Based Access Control
Buyer and seller roles enforced at both API middleware and Supabase RLS layer. A buyer account cannot reach seller dashboard routes — period, regardless of URL manipulation.
Secure File Uploads
Product image uploads are validated for MIME type and size on the server before storage. Bucket policies in Supabase Storage restrict read/write access per authenticated user.
Input Validation
All product data, pricing, and order inputs are sanitized and validated server-side before database writes — preventing injection and ensuring data integrity.
Auth Token Security
JWT-based sessions via Supabase Auth with refresh token rotation. Server-side validation on every protected route — client-reported identity is never trusted directly.

Challenges & Solutions

Problem
Cart state was being lost on page refresh — React state alone doesn't survive navigation, which is fatal for an e-commerce checkout flow.
Solution
Persisted cart state to Supabase for authenticated users and localStorage for guests, with a merge strategy on login — so no items are ever lost mid-session regardless of auth state.
Problem
Product images uploaded by sellers were loading slowly due to large file sizes, degrading the storefront experience especially on mobile.
Solution
Added client-side image compression before upload and leveraged Supabase Storage's CDN edge delivery. Load times dropped significantly — images now load from the nearest edge node to the visitor.
Problem
Sellers needed to manage inventory and view orders in one dashboard, but mixing those concerns created complex permission boundaries between what a seller could see vs. a buyer.
Solution
Built a strict role-based data access model — seller queries filter by seller_id at the RLS layer, making it structurally impossible to leak another seller's inventory or a buyer's personal order data.

The core architecture lesson in CraftyHands was that e-commerce security isn't just about payment security — it's about data isolation between user roles. That's the kind of defense-in-depth thinking I carry from security work directly into product engineering.
